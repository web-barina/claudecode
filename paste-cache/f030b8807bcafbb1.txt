# 4. 添付画像下部の説明文もサイト用に整理

画像の、

「これまで複数の制作会社様の案件をお手伝いしてきました。
担当することが多いのは、ワイヤーフレーム完成後の制作工程から公開までのディレクション・進行管理です。」

という内容は重要なので、サイトにも入れる。

ただし、そのまま長文にしすぎない。

例えば、

**これまで複数の制作会社様の案件に携わり、
制作工程から公開までのディレクション・進行管理を担当してきました。**

程度にする。

さらに重要なポイントとして、

**「どこからでも全部できます」と誤解させない。**

実際に担当することが多い領域を、

> **特に、ワイヤーフレーム完成後の制作進行を得意としています。**

と明記する。

これにより、制作会社側が、

「ワイヤーフレームまではこちらで用意するので、その後を任せられそう」

と理解できる。

# 9. PROCESSはどうするか

現在のPROCESSも「ヒアリング→計画→制作→確認→公開」という内容なので、

今回の「お手伝いできる範囲」とかなり重複する。

そのため、**PROCESSも独立セクションとして残す必要があるか再検討する。**

基本的には削除を推奨。

理由：

### お手伝いできる範囲

で、

**受注 → 要件定義 → 制作 → 公開**

をすでに説明している。

さらに、

### FOR CLIENTS

で、

**話す → 整理する → つくる → 公開**

を説明する。

ここにPROCESSまで入れると、3回同じ流れを説明することになる。

したがって、

**PROCESSは削除。**

# 17. 特に重要な視点

このサイトを見たお客様が、

> 「この人は元教員なんだ」

で終わってはいけない。

最終的に、

> **「Webに詳しくなくても、話を聞いて整理してくれて、制作をちゃんと進めてくれる人なんだ」**

と感じてもらう。

一方、制作会社の人が見た場合は、

> **「ワイヤーフレーム以降の制作進行・クライアント対応・パートナーとの連携・品質チェックまで任せられる人なんだ」**

と理解できるようにする。

つまり、

**ABOUT = 人となり・背景**

**お手伝いできる範囲 = 実務能力・対応範囲**

**FOR CLIENTS = お客様にとっての安心**

**WORKS = 実績**

という役割分担にする。

# 最終ゴール

サイトを見た人が、

**誰？**
→ Webディレクター

**どんな人？**
→ 教員経験を持ち、相手に合わせて整理・コミュニケーションできる

**何をしてくれる？**
→ 受注後の要件定義から制作・進行管理・品質チェック・公開まで

**自分にとって何がいい？**
→ Webに詳しくなくても相談でき、制作を任せて進められる

**実際にやったことは？**
→ WORKS

**どんな経歴？**
→ CAREER

**これから？**
→ NOW & NEXT

**相談したい**
→ CONTACT

という順番で、迷わず理解できるサイトにする。

**情報量を増やすのではなく、同じ情報を1回だけ、最も適切な場所で伝えること。**
