# QA Check スキル

WebページのURLを受け取り、フェーズ別・カテゴリ別の品質チェックを行ってターミナルに出力する。
チェック項目は社内チェックシート（HP/LP制作プロジェクトシート）に準拠。

## インプット形式

- **URL指定**：`https://example.com/test-page` のような公開URL（テストアップ済みURL）
- **複数URL**：カンマ区切りまたはリスト形式で複数ページ一括チェック可能
- **フェーズ指定**（任意）：「フェーズ1だけ」「フェーズ2まで」など指定があれば対応

Basic認証がかかっている場合は `https://user:pass@example.com/` の形式で渡してもらう。

### 【フェーズ1】初回テストアップ時の確認

#### SEO対応
- 見出しタグ（hタグ）がワイヤーフレーム通りか
- **TOPページのh1はヘッダーロゴ、下層ページはページタイトルがh1**になっているか
- h1は1ページに1つか / h1→h2→h3の階層が正しいか（飛び飛びNG）
- h2・h3が1つだけの状態になっていないか
- 写真・イラスト以外（見出し・表など）を画像で実装していないか
- `alt` 属性：関連見出しの内容・人物や施設は固有名称＋説明のユニークな内容か
- **リンクはJSではなくHTMLの `<a href>` で実装されているか**（JSリンクはクローラーが追えない）
- 外部サイトへのリンクは `target="_blank"` で新タブで開くか

#### レスポンシブ
- **スマホの最小幅360pxで崩れがないか**（特にタイトルの段落ちに注意）
- 画像のアスペクト比が保持されているか（`object-fit` または `width/height` 属性）
- ループ出力記事内のテキストが自動省略設定されているか（`-webkit-line-clamp` 等）
- viewport metaタグの有無・設定（`width=device-width, initial-scale=1`）

#### UI/UX
- PC・SPで追従バナーが実装されているか
- **すべてのリンクにホバーアクションが設定されているか**
  - ヘッダー・フッターのロゴ、リンクバナー画像、TOPへ戻るボタンが特に抜けやすい
- テキストリンクはopacity以外のホバーアクションか（下線・色変化・装飾など）
- パンくずが画面幅に収まらない場合は横スクロール可能か
- **横スクロールがある要素には常にスクロールバーが表示されているか**（iOS対応必須）
- **不要な横スクロールが発生していないか**（Mac：スクロールバー「常に表示」で確認）
- コンテンツが少ない場合でもフッターが最下部に配置されているか

#### CMS基本動作
- 記事一覧のアイキャッチ未設定時にデフォルト画像が設定されているか
- 記事個別ページではアイキャッチ未設定時は画像を表示しない設定か
- CMS関連記事は最新順・表示中記事は除外して表示されているか
- コピーライトの西暦は自動で年が切り替わる実装か

### 【フェーズ2】全ページ実装完了時の確認

#### SEO対応
- 全ページでtitle/descriptionが設定されているか
  - title：KW含む・KW前方・他ページと重複なし・〜70文字
  - description：120文字程度・KW含む・他ページと重複なし・KW過剰使用なし
- 全ページでOGP（og:title / og:description / og:image / og:url）が設定されているか
- ファビコンが設定されているか
- ロゴの `alt` はサイト全体で同一か
- canonical タグの有無・URLが正しいか（末尾スラッシュありで統一）

#### リンク設定
- アクセスできないページ（404リンク）が存在しないか
- 内部リンクのアンカーテキストにKWを含めているか（「詳しく見る」「こちら」のみはNG）
- パンくずのTOPリンクのアンカーテキストにKWが含まれているか（「TOP」「ホーム」はNG）
- 1ページからの発リンク数が200以内か

#### 404ページ
- 存在しないURLで正しく404が返るか
- 404ページのレイアウトが整っているか（ページ不在の告知・サイトと同一デザイン・TOPへのリンクあり）

#### フォームテスト
- 問い合わせページのロゴは非活性（クリック不可）か
- フォームページに追従導線・CTA・ヘッダー/フッターナビは設置していないか
- プレースホルダーが設定されているか
- 郵便番号欄がある場合、入力時に住所が自動入力されるか
- 電話番号欄：最小10文字・最大13文字に制限されているか
- **スマホで電話番号欄に数字キーボードがデフォルトで出るか**（`type="tel"` または `inputmode="numeric"`）
- 入力不備時は送信ボタン非活性ではなくエラー文言が表示されるか
- バリデーションのエラー文が適切か
- プライバシーポリシー同意チェックのエラー文が正しく動作するか
- プライバシーポリシーへのリンクは別タブで開くか
- 問い合わせ後にサンクスページへ遷移するか
- 自動返信メール・管理者宛通知メールが設定されているか

---

### 【フェーズ3】SEO実装完了時の確認

#### XMLサイトマップ
- `sitemap.xml` が準備されているか / noindexページは含まれていないか

#### index制御
- noindexページが正しく指定されているか（絞り込み・並べ替え等の重複回避）
- 会員サイトのログイン以降・ECのカート以降には `nofollow` が設置されているか

#### URL正規化
- canonical タグで重複ページURLが正規化されているか（末尾スラッシュありで統一）
- ページネーションの重複回避（各ページに固有URL・canonicalが各ページを参照）
- リダイレクト回数が5回以内か

#### ページスピード
- 画像が圧縮されているか
- **SP用画像は50KB以下を目安に切り分けられているか**
- `<img>` タグに `width`・`height` 属性が指定されているか（CLS防止）
- **FV以外の画像に `loading="lazy"` が設定されているか**（FVは絶対に遅延させない）
- 画像はWebP化されているか
- Google Fontsに `&display=swap` が設定されているか
- `fonts.gstatic.com` への `preconnect` が設定されているか
- `<head>` 内のレンダーブロッキングスクリプトに `async`/`defer` が付いているか
- GTMスクリプトに遅延読み込みが適用されているか
- PSI目安スコア：LCP 2.5秒以下 / CLS 0.1以下 / FCP 1.8秒以下（外部ツール確認推奨）

#### 構造化データ（schema.org）
`<script type="application/ld+json">` を抽出し実装状況をチェック：

| タイプ | 対象ページ |
|--------|-----------|
| `WebSite` | TOPページのみ |
| `Organization` または `LocalBusiness` | TOP・会社概要ページ |
| `AboutPage` | 会社概要ページ |
| `ContactPage` | お問い合わせページのみ |
| `BreadcrumbList` | TOPページ以外の全ページ |
| `ProfilePage` + `Person` | 人物情報掲載ページ |
| `Article` | 投稿個別記事ページ |
| `FAQPage` | FAQ掲載ページ |
| `JobPosting` | 採用情報ページ |
| `VideoObject` | 動画コンテンツ掲載ページ |
| `Event` | イベント情報掲載ページ |

---

### 【全フェーズ共通】コンテンツ・信頼性

- プライバシーポリシー / 住所 / コピーライト表記 / お問い合わせページが設置されているか
- URL構造にページ内容が分かる名称がついているか（複数単語はハイフン区切り）
- URLのパラメータが長すぎないか
- 電話番号はモバイルで `<a href="tel:...">` になっているか
- ダミー画像が本番用に差し替わっているか（透かし等がないか）

## 実行手順

### 1. HTMLを取得

```bash
curl -s -L -A "Mozilla/5.0 (compatible; QABot/1.0)" "<URL>" -o /tmp/qa_target.html
echo "取得バイト数: $(wc -c < /tmp/qa_target.html)"
```

### 2. CSSファイルを抽出・取得

```bash
mkdir -p /tmp/qa_css
# linkタグからCSS URLを抽出してベースURL補完しながら取得
# <style>タグ内のインラインCSSも対象
```

### 3. 解析実行（Python）

```python
python3 << 'EOF'
import re
with open('/tmp/qa_target.html', encoding='utf-8', errors='replace') as f:
    html = f.read()
# 各チェック関数を実行（詳細は references/check-items.md）
EOF
```

### 重要度の定義

| 重要度 | 記号 | 基準 |
|--------|------|------|
| 高 | 🔴 | SEOや表示に直接影響する問題（必ず修正） |
| 中 | 🟡 | 改善推奨・目視確認が必要な項目 |
| 低 | 💡 | ベストプラクティスの観点（余裕があれば対応） |

## 注意事項

- JSで動的生成されるコンテンツはHTMLフェッチでは検出できない
- フォームの送受信・メール受信確認は目視必須（スキルでは構造チェックのみ）
- ホバーアクションはCSSで検出できる項目もあるが、アニメーション系は目視確認が必要
- PSIスコアは `https://pagespeed.web.dev/` での確認が必須
- 構造化データの正当性は `https://validator.schema.org/` または `https://search.google.com/test/rich-results` で確認推奨
- WordPressの場合、`wp-content/themes/` 配下のCSSを優先的に確認
