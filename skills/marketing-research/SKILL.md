# マーケティングリサーチ統合スキル（ディレクション資料出力版）

業界・サービス名を入力に、リサーチ→分析→Excel出力までを1スキルで完結する。
出力Excelは「ディレクション資料」フォーマット（`~/Downloads/ディレクション｜サンプル架空の占いサイト.pdf` と同じシート構成）。

## クレジット節約の原則（重要）

- **サブスキルを個別に view しない。** 手順はすべてこのファイルに書いてある。
- **Web検索は最小限。** 市場3〜4回・競合4〜5回・ニーズ3〜4回の合計12回前後。SWOT・ペルソナ・ポジショニングは**追加検索なし**で既取得データから合成する。
- **中間ファイルは1本だけ**（`research.json`）。ステップごとに分割しない。
- **Excel生成は同梱スクリプトを実行**（`scripts/build_excel.py`）。openpyxlコードをその場で書き起こさない。
- 進捗報告は各ステップ1行のみ。冗長な説明をしない。

## 出典の記載（必須）

**全シートの末尾に「出典・根拠」を必ず入れる。** `build_excel.py` が自動で1行足すので、各STEPで対応キーを埋めること。

| シート | 出典に入れるもの | JSONキー |
|---|---|---|
| 市場調査 | 実際に閲覧・検索したページのURL（4〜6件） | `market.sources` |
| 競合調査 | 競合選定・各社調査で見たページのURL（各社サイト＋比較サイト等） | `competitors.sources` |
| SWOT分析 | 通常は「市場・競合・3Cの分析結果に基づく（新規調査なし）」。追加検索した場合はそのURL | `swot.sources`（任意。無ければ既定文） |
| ニーズ分析① | キーワード調査で見たページのURL（3〜5件） | `needs_sources`（トップレベル） |
| ニーズ分析② | `needs_sources` ＋ 各行の `source` URL（行ごとに実在URLを必ず入れる） | 各 `needs_qa[].source` |
| ペルソナ | 「市場調査『顧客層』・ニーズ分析・クライアント情報に基づく設計」＋根拠は各行 `basis` | `personas_sources`（任意） |
| ポジショニング | 「競合・市場・3Cの分析結果に基づく」＋各社 `note` | `positioning.sources`（任意） |

URLは**実際にアクセスしたものだけ**。推測のURLを書かない。閲覧できなかった場合は「検索スニペットのみ」と明記。

## 入力パターン

| パターン | 例 | 対応 |
|---|---|---|
| A：業界名のみ | 「オンライン占い業界を分析して」 | 競合はWeb検索で自動選定（5〜6社、中小中心） |
| B：競合指定 | 「競合はA社・B社・C社で」 | 指定社を優先。6社未満なら自動補完 |
| C：ヒアリングシートあり | 会社情報・目的・ターゲット等のテキストを一緒に渡される | その内容を `client` として取り込み、SWOT「Webサイトへの打ち出し」やペルソナ、ポジショニングのクライアント位置に反映 |

ヒアリングシートを渡されていない場合は `client` を空にして進める（分析は業界一般＋競合ベースで成立させる）。
ヒアリングシートそのもの・制作スケジュールのシートは**出力しない**（ユーザーが後から追加する運用）。

## 実行フロー

```
[入力解析] 業界名 / サービス名 / 競合指定 / ヒアリング内容 を抽出
   ↓  作業ディレクトリ: /tmp/research_{業界名}/   （業界名のスペースは_に変換）
STEP 1  市場調査     → research.json の "market" を埋める      （Web検索 3〜4回）
STEP 2  競合調査     → research.json の "competitors" を埋める  （Web検索 4〜5回）
STEP 3  3C分析(内部) → research.json の "_3c" を埋める          （検索なし・合成のみ／シート化しない）
STEP 4  SWOT分析     → research.json の "swot" を埋める          （検索なし・合成）
STEP 5  ニーズ分析   → research.json の "needs_keywords" / "needs_qa" を埋める （Web検索 3〜4回）
STEP 6  ペルソナ設計 → research.json の "personas" を埋める      （検索なし・合成）
STEP 7  ポジショニング → research.json の "positioning" を埋める （検索なし・合成）
STEP 8  Excel出力    → scripts/build_excel.py を実行
```

進捗報告フォーマット：
```
🔍 STEP 1/7 市場調査…
✅ STEP 1/7 完了
...
📊 Excelを出力中…
✅ 完了：~/Desktop/marketing_research_{業界名}_{YYYYMMDD}.xlsx
```

## research.json の作り方

`templates/research.example.json` に完成例がある。**最初に**この空の骨組みを `/tmp/research_{業界名}/research.json` に作り、各STEPで対応キーを埋めていく（毎STEP上書き保存）。

トップレベルキー：
```json
{
  "industry": "業界名",
  "service_name": "サービス名（あれば）",
  "analyzed_at": "YYYY-MM-DD",
  "client": { ... },          // ヒアリングがあれば。なければ {}
  "market": { ... },          // STEP1
  "competitors": { ... },     // STEP2
  "_3c": { ... },             // STEP3（内部・非出力）
  "swot": { ... },            // STEP4
  "needs_keywords": [ ... ],  // STEP5
  "needs_qa": [ ... ],        // STEP5
  "needs_sources": [ ... ],   // STEP5（キーワード調査で見たURL）
  "personas": [ ... ],        // STEP6
  "positioning": { ... }      // STEP7
}
```

---

## STEP 1：市場調査 → `market`

検索クエリ（3〜4回。1回で複数観点を拾えたら減らす）：
```
「{業界名} 市場規模 特徴 慣習 日本 2025」
「{業界名} 価格帯 相場 料金」
「{業界名} 集客 販売促進 チャネル トレンド 2025」
「{サービス名 or 業界名} 顧客層 ターゲット」
```

`market` の構造（PDF「市場調査」シートの行に対応）：
```json
"market": {
  "market_size": "市場規模（わかる範囲。不明なら『公開統計なし・推定』）",
  "industry_definition": "どんなサービス・商品があるか（150〜250字）",
  "service_breakdown": "業界のサービス・商品の細分化（手段/課金/機能/周辺商材などを箇条書き。改行\\nで区切る）",
  "industry_norms": ["業界の常識・慣習（5〜8項目）"],
  "major_players": "市場をリードする企業・プラットフォーム（種別ごとに）",
  "price_range": "一般的な価格。必ず円で具体数字。クライアント現行価格があれば相場比較も1文",
  "distribution": ["流通・提供方法（3〜5項目）"],
  "promotion": ["販売促進方法（4〜6項目。番号付きでも可）"],
  "customer_segments": "BtoB/BtoC の別＋ターゲット層の特徴（男女比・年代・相談内容など、150字前後）",
  "trends": ["消費者動向・いま求められていること（4〜6項目）"],
  "sources": ["参考URL"]
}
```
注意：情報が薄い業界は「一部推定を含む」と `market_size` 等に明記して続行。

## STEP 2：競合調査 → `competitors`

選定：パターンB指定社を優先。不足分・パターンAは検索で補完。**大手2〜3社＋中小/ニッチ3〜4社**で計5〜6社。

検索クエリ（4〜5回）：
```
「{業界名} 比較 おすすめ 会社」            ← 選定用（パターンA）
「{各社名} 特徴 料金 サービス」×2〜3社分   ← まとめて調べる。1社1クエリまで
「{業界名} 競合 サービス 違い」
```
各社サイトを1件ずつ丁寧に読み込まない（コスト増）。検索スニペット＋必要なら代表1社のみ閲覧。

`competitors` の構造（PDF「競合調査」シート：縦=調査項目、横=各社）：
```json
"competitors": {
  "selection_criteria": "競合選定基準の説明（1〜2文）",
  "companies": [
    {
      "name": "社名・サービス名",
      "size": "大手 / 中小 / スタートアップ",
      "url": "https://…（未確認なら『公式サイトで確認』）",
      "catchcopy": "キャッチコピー・タグライン",
      "service": "主なサービス内容（60字前後）",
      "price_range": "価格帯（円）",
      "design": "サイトデザインの印象（配色・トーン、40字前後）",
      "features": "主な機能（予約/レビュー/会員特典など）",
      "content": "コンテンツの特徴",
      "coverage": "専門領域・取扱い範囲（PDF例では占術種類。業界に応じて『対応領域』『取扱いジャンル数』等）",
      "operation": "対応時間・体制（24時間対応など）",
      "highlight1": "特徴①（他社にない売り）",
      "highlight2": "特徴②",
      "highlight3": "特徴③（なければ空文字）",
      "strengths": ["強み 2〜3項目"],
      "weaknesses": ["弱み・課題 1〜2項目（推定は『（推定）』と明記）"]
    }
  ],
  "sources": ["参考URL"]
}
```

## STEP 3：3C分析（内部・シート化しない） → `_3c`

**検索しない。** STEP1・2の結果だけで合成する。SWOT/ペルソナ/ポジショニングの土台。
```json
"_3c": {
  "customer": {
    "key_needs": ["顧客の主要ニーズ 4〜6"],
    "buying_triggers": ["購買・登録・問い合わせのきっかけ 3〜5"],
    "decision_factors": ["選定の決め手 3〜5"]
  },
  "competitor": {
    "landscape": "競合状況の総評（120字）",
    "common_strengths": ["競合が共通で持つ強み 3〜4"],
    "common_weaknesses": ["業界全体の弱点・手薄な点 2〜3"],
    "white_space": ["競合が手薄なポジション・ニーズ 2〜3"]
  },
  "company": {
    "differentiation_hints": ["自社が取れる差別化の方向性 3〜5（clientがあればそれ基準）"],
    "recommended_positioning": "推奨ポジションの方向性（100字）"
  }
}
```

## STEP 4：SWOT分析 → `swot`

**検索しない。** `_3c`・`competitors`・`client`（あれば）から合成。PDF「SWOT」シート＝各項目に「Webサイトへの打ち出し」を対で書く。
- 強み・弱み＝内部環境（`client` があればクライアント、なければ「この業界で自社が取りうる立ち位置」として記述）
- 機会・脅威＝外部環境（市場動向・社会変化・競合動向）
- 「Webサイトへの打ち出し」は**具体的なページ施策・コピー方向**まで落とす

```json
"swot": {
  "strengths":     [{ "item": "強みの内容", "web": "Webサイトへの打ち出し方（改行\\n可・複数施策）" }],
  "weaknesses":    [{ "item": "弱みの内容", "web": "Webでの対処・カバー方法" }],
  "opportunities": [{ "item": "追い風となる外部環境", "web": "打ち出し方" }],
  "threats":       [{ "item": "リスクとなる外部環境", "web": "Webでの対応策" }],
  "cross": {
    "SO": "強み×機会：最も攻める戦略（100字）",
    "ST": "強み×脅威：強みで脅威を回避（100字）",
    "WO": "弱み×機会：弱みを補い機会を取る（100字）",
    "WT": "弱み×脅威：最も避けるリスク（100字）"
  }
}
```
項目数の目安：強み4〜5 / 弱み3〜4 / 機会3〜4 / 脅威3〜4。

## STEP 5：ニーズ分析 → `needs_keywords` / `needs_qa`

検索クエリ（3〜4回）：
```
「{業界名 or サービス} よくある質問 悩み」
「{サービス} 選び方 比較 どこがいい」
「{業界名} 検索キーワード 需要」
（必要なら）Q&Aサイト（Yahoo!知恵袋・教えて!goo 等）を1〜2ページ確認
```

### `needs_keywords`（PDF「ニーズ分析①：キーワード」）
```json
"needs_keywords": [
  {
    "keyword": "検索キーワード（複合語。例：占い 当たる 恋愛）",
    "volume": "月間平均検索ボリューム概算（例：1万〜10万 / 1,000〜1万。推定は『（推定）』）",
    "problem": "検索者が抱えている課題（・区切りで複数可、改行\\n）",
    "site_use": "サイトへの活用案。PDFに倣い先頭に【きっかけづくり】【信用を得る】【不安の解消】等の見出し"
  }
]
```
8〜12件。近い意図のキーワードはまとめて1行にしてよい（PDFもグルーピングしている）。

### `needs_qa`（PDF「ニーズ分析②：検索ワード質問」）
```json
"needs_qa": [
  {
    "question": "実際の質問・相談の要約（Q&Aサイト等から。80〜150字）",
    "source": "情報ソースURL（実在するもののみ。なければ空文字）",
    "problem": "抱えている課題（・区切り）",
    "site_use": "サイトへの活用案（具体ページ・コンテンツ）",
    "keyword": "この質問を表すタグ（例：占いへの信憑性・信頼 / 安心を求める）"
  }
]
```
6〜8件。

### 出典（必須）
キーワード調査で実際に見たページのURLをトップレベル `needs_sources`（配列, 3〜5件）に入れる。
`needs_qa[].source` は行ごとに実在URLを必ず入れる（無い場合は「検索結果のみ」と明記し空文字にしない）。

## STEP 6：ペルソナ設計 → `personas`

**検索しない。** `market.customer_segments`・`_3c.customer`・`needs_*`・`client`（ターゲット記述があれば最優先）から合成。
PDF「ペルソナ」シート＝第1〜第3ペルソナ、各項目に「詳細」と「メモ（根拠）」。

```json
"personas": [
  {
    "no": 1,
    "title": "第1ペルソナ（メイン顧客）",
    "rows": [
      { "item": "年齢",  "detail": "42歳", "basis": "根拠（例：利用者が多いのは40代女性 という設定から）" },
      { "item": "性別",  "detail": "女性", "basis": "…" },
      { "item": "家族構成", "detail": "夫と中学生の子ども1人", "basis": "…" },
      { "item": "居住地", "detail": "…", "basis": "…" },
      { "item": "ライフスタイル（働き方・生活習慣・興味・関心）", "detail": "…（150字前後）", "basis": "…" },
      { "item": "抱えている課題", "detail": "・…\\n・…\\n・…", "basis": "…" },
      { "item": "検索時のシチュエーション", "detail": "いつ・どこで・どんなワードで検索し何を求めるか", "basis": "…" }
    ]
  }
]
```
3名：第1＝メイン（`client` のメインターゲット。占い例では40代女性）、第2＝最若年層、第3＝中間層。
`client` にターゲット記述がなければ、市場データの中心セグメントを第1に据える。

## STEP 7：ポジショニングマップ → `positioning`

**検索しない。** `competitors`・`_3c` から軸を決め、各社を配置。
PDF例＝X軸「〜20代 ⇔ 50代〜（年齢層）」× Y軸「低価格(100円/分) ⇔ 高価格(300円/分)」のバブルチャート。クライアントは空白地帯に配置。

軸候補から**差別化できる2軸**を選ぶ（全社が同じ側に固まる軸はNG）：
価格 / 品質 / 専門性(総合⇔特化) / 対象(個人⇔法人) / スピード / サポート(セルフ⇔フル) / 顧客年齢層 / 地域(全国⇔密着)

```json
"positioning": {
  "axis_x": { "left": "左ラベル", "right": "右ラベル", "why": "この軸にした理由" },
  "axis_y": { "bottom": "下ラベル", "top": "上ラベル", "why": "理由" },
  "companies": [
    { "name": "社名", "x": 0.7, "y": 0.8, "size": 1.2, "is_client": false, "note": "この位置の根拠" }
  ],
  "client": { "name": "クライアント名 or 自社", "x": 0.85, "y": 0.8, "note": "この空白地帯を推奨する理由（100字）" },
  "insight": "マップ全体から読み取れる示唆（150字）",
  "alt_axes": [ { "x": "代替X軸", "y": "代替Y軸", "when": "有効な場面" } ]
}
```
x, y は 0.0〜1.0（0=左/下、1=右/上）、size は 0.8〜2.0（規模感）。
`client` は必ず「競合が少ないゾーン」に置く。alt_axes は1〜2セット。

## STEP 8：Excel出力

```bash
python3 ~/.claude/skills/marketing-research/scripts/build_excel.py \
  --input /tmp/research_{業界名}/research.json \
  --outdir ~/Desktop
```

- 出力：`~/Desktop/marketing_research_{業界名}_{YYYYMMDD}.xlsx`
- シート：`市場調査` / `競合調査` / `SWOT分析` / `ニーズ分析①キーワード` / `ニーズ分析②検索ワード質問` / `ペルソナ` / `ポジショニングマップ`
  （＝PDFから「スケジュール」「ヒアリングシート」「ワイヤーフレーム」を除いた構成。3C分析シートは無し）
- 同時にバブルチャートを `~/Desktop/positioning_map_{業界名}.png`（`ポジショニングマップ` シートに貼付）と `~/Desktop/positioning_map_{業界名}.svg`（共有用）に書き出す。
- スクリプトがJSON検証エラーを出したら、該当キーを埋めて再実行。

出力後、ユーザーに1行で報告し、「ヒアリングシート・制作スケジュール・WFリンクのシートはこのファイルに追記してください」と添える。

## エラーハンドリング

- 情報が少ない業界：「一部推定を含む」と明記して続行（止めない）
- 競合が指定数に満たない：自動補完
- 各STEPでエラー：内容を1行報告し次STEPへ（全体を止めない）
- `build_excel.py` が無い/壊れている場合のみ、openpyxlで直接生成（最終手段）
